Decisions

Fixed

History belongs to its trip

The foreign key is histories.trip_id, so the old has_one :trip — paired with belongs_to :history on Trip, for a column that never existed — pointed the association the wrong way and would have raised the first time either side was used.

Moved

Times live in stop_times, not on trips

The trips.departure and trips.arrival columns were removed; they only ever duplicated the first and last stop_time. Trip#departure, #arrival and #duration_minutes read the same as before, now computed, and return nil while a trip is half surveyed.

Moved

The mode belongs to the route, not the trip

trips.vihicle_id is gone. Trip#vihicle is now has_one :through and Vihicle#trips is has_many through: :routes, so a trip can no longer disagree with its own route about which vehicle runs it.

Modelled

Frequency instead of timetable

Tricycles, habal-habal and most jeeps leave when full. They get one representative trip per route plus frequencies rows with exact_times: false, which is how GTFS expresses headway-based service. Ferry, bus and van get one trip per real departure and no frequency row.

Open

histories.user_id still has no database constraint

It is a plain indexed integer while trip_id has a real key. Rails validates belongs_to by default, so ordinary writes are covered — but nothing stops an orphan arriving through a direct SQL write or a bulk import. The asymmetry is inherited from the original migration and left as it was.

Open

No importer, and no shapes

Nothing reads data/gtfs/ into these tables yet; gtfs_id is what that importer should upsert on. shapes.txt has no table behind it at all — worth leaving until route geometry is actually collected.
